# 1. use ADRs

Date: 2026-09-17

## Status

accepted

## Context

This is a new project and we want to make sure that all our architectural decisions are documented.

## Decision

Use ADRs (see https://adr.github.io/) to document architectural decisions here in docs/adr.

## Consequences

The history of architectural changes is legible.

The current intended architecture is legible.

We need to take care to write just enough but not too much detail about architectural changes. We could write too much detail and tie ourselves in bureaucracy.

The actual architecture and the documented architecture may drift, and will need regular coherence checks.
