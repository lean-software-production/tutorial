Start with one coding agent. Grow a system you can configure, observe and steer.

Welcome students. This deck shows where the tutorial is going, then gets everyone into the first homework.

The whole journey

The factory grows by one pressure at a time.

1Automate

Turn a seed into working software, one task at a time.

2Compose

Make routes, machines, jobs and targets explicit.

3Operate

Run work in parallel, watch it live and intervene.

Destination: an observable, steerable system—not one enormous prompt.

How the tutorial works

1Fetch

Your coding agent downloads one homework into spec/.

2Build

Make the feature files pass. They are your acceptance tests.

3Repeat

Fetch again. Existing step definitions carry forward.

You choose the language, libraries and design.

First things first

Get started

Fork the starter, open your agent in the right folder, then fetch Homework 1.

1 · Fork the starter

Your fork becomes your capstone repository.

  1. Open capstone-project-starter.
  2. Choose Fork.
  3. Give the fork your capstone project’s name.
The homeworks build Tetris first. Your capstone comes later.

2 · Clone and check

Clone your fork, then check the tools without calling a model.

git clone https://github.com/YOUR-NAME/YOUR-CAPSTONE.git
cd YOUR-CAPSTONE
bin/doctor

Using a Codespace or Dev Container? Open it, authenticate one agent, then run bin/doctor.

Ready means: Bash, Git, Node, npm and all three agent CLIs are present, and at least one agent is configured.

3 · Start your coding agent

Start it inside tetris/.factory. That is where it finds the course instructions and skills.

cd tetris/.factory

pi       # or: claude
         # or: codex
Check: your agent’s working directory ends in tetris/.factory.
Do not start the agent at the repository root. The local AGENTS.md and project skills are under tetris/.factory.

4 · Fetch Homework 1

Now talk to the coding agent. These are requests in its chat, not shell commands.

You fetch iteration
Then you coach me

The first request downloads the spec. The second walks you through it one passing example at a time.

Homework 001

Basic unvalidated loop

Seed

Describe the product: terminal Tetris.

Plan

The agent breaks the seed into tasks.

Do

One pass completes one task and commits it.

Factory gainsA small, stateless loop that turns a seed into working code.
The factory does not inspect plan.md. The agent owns the plan and returns structured JSON; the factory routes on fields, not prose.

Run your first factory

You choose the executable’s name. Suppose it is ./factory:

Write the plan
./factory
Do one task
./factory
Finish the plan
./factory --all
Play the result
cd .. && npm start
Small win: a real game appears, one agent task and one commit at a time.

After the first loop

Seven iterations,
one story

Each homework exposes the next hidden assumption and turns it into a capability.

Homework 002

Checking the work

Planner

Keeps and advances the plan.

Doer

Implements the next task.

Validator

Checks through a lens you choose.

Factory gainsSpecialised machines, validation findings and bounded retry.

Homework 003

The assembly line

The route leaves your code and becomes a graph the factory reads.

  • Machines are named nodes
  • Result fields choose labelled edges
  • Change the route without changing factory code
Factory gainsA configurable workflow instead of a hard-coded sequence.

Homework 004

Jobs and targets

Factory

Moves into its own codebase.

Target

Owns its product, lines and machines.

Job

Remembers a target, line, seed and plan.

./factory --job tetris --target ../tetris --line careful --seed ../tetris/seeds/tetris.md
Factory gainsMany resumable jobs across many codebases.

Homework 006

Watching

The factory becomes a service. Start a job, get your terminal back, then attach.

./factory --job tetris …
# started job tetris

./factory watch tetris
# planner | …
# doer    | …
# tokens  | …

Machines speak ACP: the Agent Client Protocol. Output and token usage stream as they work.

Factory gainsBackground jobs, durable output and live cost visibility.

Homework 007

Steering

Watching becomes a conversation. Send a message to the machine working now.

./factory say tetris doer \
  "use curses, not print"

A message belongs to that machine run. For a lasting instruction, change the seed, plan or machine prompt.

“I can see what you’re doing—and redirect you before the turn ends.”
Factory gainsTargeted, live intervention in running agent work.

Keep the learning loop small

Do
  • Treat features/ as the spec
  • Take one failing example at a time
  • Keep state in files
  • Route on structured results
Don’t
  • Edit the fetched spec
  • Hide intelligence in factory code
  • Parse an agent’s prose
  • Build all seven homeworks at once

When the suite passes, say fetch iteration again.
